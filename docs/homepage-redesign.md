# 老板驾驶舱首页改版设计

目标：打开首页 10 秒内掌握全局、知道今天要做什么。数据示例取自 2026-08-19 15:41-15:45 的真实 Skill 输出快照。

## 一、设计原则

1. 信息极简：首屏只保留 5 个模块 + 1 条全局结论条；低优先级事项默认折叠，不入首页。
2. 结论先行：每个模块标题直接给结论和数字（如「11 项需处理」），不展示无结论的原始列表。
3. 可行动：每条信息都有唯一主按钮（去处理 / 回复 / 查看），点击直达对应页面或单据。
4. 不造数：源系统没有的字段显示「未获取 / 未接入」，不用占位数字或推测填充；金额、日期、人名一律与源系统一致。

## 二、布局结构

### 桌面端（宽度不低于 1024px）

    +--------------------------------------------------------------+
    | 侧栏(72) |  顶栏：Boss Jarvis / 驾驶舱 · 刷新 · 自定义模块     |
    |          +--------------------------------------------------+
    |          | 0 全局结论条（10 秒区）：今日 N 项需处理 · 紧急 N    |
    |          |   · 邮件待回复 N · 开始处理第 1 项 · 更新时间        |
    |          +-------------------------------+------------------+
    |          | 1 今日待办提醒（Top 3 紧急排序） | 2 今日需处理事项  |
    |          |   每条：结论 + 来源时间 + 去处理  |   聚合计数 + 分类 |
    |          +-------------------------------+------------------+
    |          | 3 经营情况速览（5 张指标卡，一行排布）                |
    |          +-------------------------------+------------------+
    |          | 4 风险提示与建议（影响程度+AI建议） | 5 待回复邮件 Top3|
    +--------------------------------------------------------------+

阅读动线即优先级：结论条 3 秒，模块 1 用 4 秒，模块 2 和 3 用 3 秒；模块 4 和 5 在首屏下方承接。

### 移动端（宽度低于 768px）

单列纵向排布，顺序严格为 0/1/2/3/4/5；结论条中关键数字放大 1.5 倍；模块 1 的行内主按钮变为整行按钮。

## 三、模块字段与数据来源

### 0 全局结论条

| 字段 | 来源 | 当前值示例 |
|---|---|---|
| 需处理总数 / 紧急数 | boss-cockpit.json 的 homepage.kpis（mustDoNow、focusToday） | 11 / 2 |
| 待回复邮件数 | company-mail.json 中 rows[].analysis.needsReply 计数 | 8 |
| 数据更新时间 | 各 Skill 输出 fetchedAt 取最大值 | 08-19 15:45 |
| 主按钮 | 跳转模块 1 第一条对应的处理页 | 开始处理第 1 项 |

### 1 今日待办提醒

排序规则：红色大于黄色大于绿色；同级按 priorityScore 降序；只显示前 3 条，其余折叠进模块 2。

| 字段 | 来源 | 示例 |
|---|---|---|
| 标题 | reminder-center / OA 待办 rows[0] | 田一怡打卡异常申请 |
| 紧急度 | reminder-center 的 homepageItems[].level | red |
| 来源 + 时间 | source 与 time 字段 | OA 待办 · 08-18 13:11 |
| 截止时间 | OA 详情或邮件 analysis.explicitDeadline；未获取时显示「按紧急度置顶」 | 未获取 |
| 处理动作 | OA 跳待办弹层审批；邮件跳邮件页回复 | 去处理 |

### 2 今日需处理事项

| 字段 | 来源 | 示例 |
|---|---|---|
| 需处理总数 | boss-cockpit 的 homepage.kpis.total 去除绿色 | 11 |
| 分类计数 | OA total；邮件 needsReply 计数；日历 count | OA 审批 3 / 邮件 8 / 会议 0 |
| 紧急标记 | level 为 red 的分类计数标红 | 2 项紧急 |
| 折叠说明 | hiddenLowPriorityCount | 低优先级已折叠 16 项 |

### 3 经营情况速览

5 张卡：本月收入 / 年度利润 / 应收余额 / 逾期应收 / 今日收入确认。每卡字段：数值、口径单位、同环比箭头、异常标记。

| 字段 | 来源 | 当前状态 |
|---|---|---|
| 今日收入确认（笔数与金额） | hongyi-today-metrics 的 metrics.todayRevenueConfirmations | 0 笔 / 0.00 |
| 本月收入、年度利润 | hongyi-business-overview 部门看板字段 | 未获取（字段待接入） |
| 应收余额、逾期应收 | 同上 receivableBalance 与 overdueReceivable | 未获取 |
| 同环比 | 需 Skill 补上期值字段 | 未接入，显示占位不造数 |
| 异常标红规则 | 逾期应收超过阈值（阈值在系统配置中设置） | 待接入 |

### 4 风险提示与建议

数据源：reminder-center 红黄项 + hongyi 首页项 + 邮件周报中的经营性风险（如项目超期率）。每条字段：

| 字段 | 说明 | 示例 |
|---|---|---|
| 风险结论 | 一句话，含关键数字 | 在跟项目超期 52 个，占比 42% |
| 影响程度 | 高 / 中 / 低；高为影响收入、现金流或合规，中为影响效率，低为观察项 | 高 |
| 来源 + 时间 | 源系统与采集时间 | 项目进度跟踪简报 · 08-14 |
| AI 建议 | 可执行动作：谁在什么时间前做什么 | 要求项目办输出超期 Top10 清单，周五前闭环 |

### 5 待回复邮件

| 字段 | 来源 | 示例 |
|---|---|---|
| 待回复数 / 未读数 | company-mail needsReply 计数与 count | 8 / 25 |
| 前 3 封发件人、主题、摘要 | rows 按 urgency 与时间排序 | 项目进度跟踪简报 |
| 回复判断依据 | analysis.replyBasis | 正文包含明确请求动作 |
| 动作 | 回复按钮在 Mail 客户端打开草稿，不代发 | 回复 |

## 四、交互与状态

- 实时性：沿用现有自动刷新（默认 15 分钟，可配 5-60 分钟）；每个模块页脚标注来源与更新时间；刷新失败显示「未获取」，不用旧数据冒充新数据。
- 模块自定义：顶栏「自定义」打开侧抽屉，支持上移、下移排序与显隐切换，配置持久化；原型存 localStorage，App 落地存 UserDefaults。
- 空状态：无待办时模块 1 显示「今日无紧急事项」正向卡片（绿色对勾 + 一句收尾语）；无风险时模块 4 显示「当前无高风险项」。
- 动作审计：所有去处理、回复、审批的点击与执行结果写入审计日志；OA 审批仍在弹层内点同意或不同意后直接执行并留痕；邮件只打开草稿，不代发。

## 五、与现有首页的差异与删减

| 现有模块 | 处置 | 理由 |
|---|---|---|
| 今日判断 + 3 张决策卡 | 压缩为 0 结论条 | 原区域约 176px 高且含建设口径文案；结论条同样给判断但省三分之二空间 |
| CommandBar（大黑按钮 + 4 个分段入口） | 删除独立命令条，主按钮并入结论条 | 大黑胶囊占 90px 高度但信息量为 1；分段入口与指标卡重复 |
| 4 张指标卡（今日全景 / 统一提醒 / 部门看板 / 完整度） | 重构为 2 聚合卡 + 3 经营速览 | 原卡混合系统建设视角（完整度、待验）；新版只留老板决策字段 |
| 今日必须处理 + 日期条 | 日期条删除，列表改为模块 1 | 日期条无点击语义、占 68px；按紧急度排序比按日期更有行动指向 |
| 待确认面板 | 降级：确认队列入口并入 2 的分类计数 | 写操作确认是流程状态，不是首屏信息；确认中心页保留完整能力 |
| 运行底座（OA 主链路等 4 卡） | 移出首页 | 属于系统可信度说明，面向建设者；在系统配置与 Skill 管理查看 |
| 经营情况（深页） | 首页取 5 个核心指标做模块 3 | 全量 15 个以上指标留在经营情况页 |
| 邮件（深页） | 首页取待回复前 3 封做模块 5 | 未读 25 封全列会淹没重点 |

新增能力：全局结论条（跨源一句话）、风险与 AI 建议模块（现首页无独立风险视图）、模块自定义、正向空状态。
